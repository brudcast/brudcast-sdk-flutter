# Brudcast Flutter SDK

In-app messaging and push notifications for Flutter apps on Brudcast, on Android and iOS. The
plugins run the native [Android](https://github.com/brudcast/brudcast-sdk-android) and
[iOS](https://github.com/brudcast/brudcast-sdk-ios) SDKs: rendering, storage, networking, the event
queue and triggers stay native, and Dart forwards calls to them.

| Package                                         | What it does                                                                  |
| ----------------------------------------------- | ----------------------------------------------------------------------------- |
| [`brudcast_flutter`](packages/brudcast_flutter) | Core: configuration, identity, events, the action handler. Always needed      |
| [`brudcast_in_app`](packages/brudcast_in_app)   | In-app messages, the inbox, `InboxController` and `BrudcastInboxMessage`      |
| [`brudcast_push`](packages/brudcast_push)       | Push: the FCM token from `firebase_messaging`, permission, foreground display |

Each package is a plain Flutter plugin with its own native dependency, so a push-only app never
ships the in-app renderer. The packages share one version with the native SDKs they run.

Start with the [`brudcast_flutter` README](packages/brudcast_flutter/README.md).

## Example app

[`example`](example) is a small app built the way a customer's app would use the SDK: sign-in
through a backend that computes the user hash, a shop with checkout events, an inbox built with
`InboxController`, and an account screen. See its [README](example/README.md).

## Develop

The repository is a [pub workspace](https://dart.dev/tools/pub/workspaces) holding the three
packages and the example.

```sh
flutter pub get
for package in packages/*; do (cd "$package" && flutter analyze && flutter test); done
```

The channels between Dart and native code are generated by [Pigeon](https://pub.dev/packages/pigeon)
from `pigeons/messages.dart` in each package. After changing one, regenerate and commit the output:

```sh
(cd packages/brudcast_in_app && dart run pigeon --input pigeons/messages.dart)
```

### Against unreleased native SDKs

The plugins pin the native SDKs exactly: `brudcastSdkVersion` in each `android/build.gradle.kts`
and `exact:` in each `ios/<package>/Package.swift`. To build against native changes that are not
released yet:

- **Android:** publish the native SDK to Maven Local, then build with `-PbrudcastMavenLocal=true`, or
  with `ORG_GRADLE_PROJECT_brudcastMavenLocal=true` in the environment for `flutter run` and
  `flutter test`:

  ```sh
  (cd ../brudcast-sdk-android && ./gradlew publishToMavenLocal -PsdkVersion=0.2.0)
  (cd example && flutter build apk --debug -PbrudcastMavenLocal=true)
  ```

- **iOS:** point `BRUDCAST_IOS_SDK_PATH` at a checkout of `brudcast-sdk-ios`. The directory must be
  named `brudcast-sdk-ios`, the package identity the plugins refer to:

  ```sh
  BRUDCAST_IOS_SDK_PATH="$PWD/../brudcast-sdk-ios" flutter build ios --simulator --no-codesign
  ```

CI does both from the native repositories at `NATIVE_SDK_REF`, a repository variable that defaults
to the release tag.

[RELEASING.md](RELEASING.md) covers publishing to pub.dev.
